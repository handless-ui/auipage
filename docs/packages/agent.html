Package 10@auipage/agent

智能体对话循环：在 @auipage/model 之上处理多轮工具调用（模型要调工具 → 执行 → 结果回灌 → 继续生成），并提供 CreateTool 把服务端工具调用桥接到浏览器。

01

基本用法

agent.js
import { Agent } from "@auipage/agent";

const agent = new Agent({
    model: {
        model: "gpt-4o-mini",
        apiKey: "your-api-key",
        baseURL: "https://api.openai.com/v1"
    },
    systemPrompt: "你是一个简洁、乐于助人的助手。",
    maxSteps: 8                                     // 可选，工具循环上限；0 表示不限制（默认）
});

const answer = await agent.generate([
    { role: "user", content: "用一句话介绍 JavaScript" }
]);
02

工具循环

一次 generate 内部可能跑好几轮，全部由 Agent 接管：

loop
模型返回 tool_calls
   → 逐个执行（后端 execute / 前端下发）
   → 结果作为 role: "tool" 的消息回灌
   → 再次请求模型
   → 直到没有新的 tool_calls 为止（最多 maxSteps 轮）
业务侧不需要写循环。你要做的是"把工具执行好"， 以及"把每一段文本/思考增量转给页面"—— 前者是 execute，后者是 CreateTool。

maxSteps0.2.0 新增 默认 0，即不限步数；设成正数后超过上限会抛出明确错误， 适合给线上对话兜底，防止模型陷入无限工具循环。

Agent 也接受 signal0.2.0 新增：abort 后本轮以错误 reject，配合 AuiPage.stop() 的 context.signal 一起用就能真正中断请求（stop 当成功收尾，cancel 当取消）。

03

前后端工具桥接：CreateTool

Agent 跑在服务端、部分工具必须浏览器执行时，用 CreateTool 包装。 它接收一个有 send(data) 方法的消息流，在工具执行节点把事件推给页面， 并支持页面把结果回传唤醒挂起的调用。

server.js
import { Agent, CreateTool } from "@auipage/agent";
import { MessageStream } from "@auipage/core";

const ms = new MessageStream(
    data => res.write("data: " + JSON.stringify(data) + "\n\n"),
    () => res.end()
);
const ct = new CreateTool(ms);

const tools = [
    // 后端工具：带 execute，在服务端执行
    ct.create({
        description: { /* name: "readPlain" */ },
        execute({ filepath }) {
            return readFile(filepath);
        }
    }),

    // 前端工具：不带 execute，调用挂起，等页面回传结果
    ct.create({
        description: { /* name: "showPlain" */ }
    }, { timeout: 60000 })                            // 可选，等页面回传的超时（毫秒）
];

const agent = new Agent({ model: { /* ... */ }, tools });
创建方式执行位置流程
ct.create({ description, execute })服务端Agent 直接执行，结果回灌模型
ct.create({ description })浏览器事件推给页面 → 挂起 → 页面回传 → 唤醒继续；默认等 30 秒，可用 { timeout }0.2.0 新增 调整
失败怎么表现0.2.0 修复：工具抛错（后端 execute 抛出、前端回传 status: "error"、等待超时）时， 事件里仍然只有 status 表示成败（result 不保证可读）， Agent 侧会把它转成一段 运行出错: ... 的文本回灌模型，让模型自己决定要不要重试， 整轮对话不会因此中断。
04

为什么这样设计

读文件、查数据库的工具必须在服务端；取本地时间、弹窗让用户确认的工具必须在页面。 两边的描述是同一套（description 就是模型看到的工具定义）， 差异只在"谁来执行、结果怎么回来"。

CreateTool 把这个差异收敛成一个 execute 的有无， 于是模型侧看到的是同一份工具列表，页面侧收到的只是"需要你执行"的事件。

05

这个包不是必须的

你的情况更合适的选择代价
工具全在服务端OpenAI Agents SDK、LangChain、Vercel AI SDK生态更大，抽象更重
只有一两个工具自己写 while 循环要处理 tool_calls 回灌与终止条件
不需要工具直接用 @auipage/model 或官方 SDK少一层封装
工具必须在浏览器执行自己做 SSE 下发 + 结果回传 + 挂起唤醒等于重写 CreateTool，容易漏状态

它最独特的价值是前后端工具桥接。如果工具都在服务端，别的 Agent 框架同样好用。
