Package 12AuiPage

AuiPage 是 @auipage/core 的入口类，把 Adapter（数据侧）和 Runtime（UI 侧）粘合起来，维护当前会话、消息历史与流式对话状态。

01

构造

main.js
import { AuiPage } from "@auipage/core";

const page = new AuiPage({
    adapter: {
        ChatTransport:  chatTransport,    // ChatTransportAdapter 实例
        MessageHistory: messageHistory,   // MessageHistoryAdapter 实例
        ThreadList:     threadList        // ThreadListAdapter 实例
    },
    runtime: {
        ThreadList:  threadListUI,        // ThreadListRuntime 实例
        ChatContent: chatUI               // ChatContentRuntime 实例
    },
    tools: [],                            // 可选：页面侧工具列表
    stopTimeout: 5000                     // 可选：stop() 兜底收尾时长，默认 5000ms（0.2.0 新增）
});

实例按 name 属性去后缀挂载：基类构造时内置 name，如 ChatTransportAdapter → page.adapter.ChatTransport。 自定义子类可覆盖 name 改变挂载位置。挂载后每个实例上写入 aui 反向指向页面实例。

构造后立即调用 adapter.ThreadList.list()，结果传给 runtime.ThreadList.init() 完成首次渲染。

02

实例属性

属性说明
adapter按 name 映射后的适配器集合
runtime按 name 映射后的运行时集合
tools_execute工具名 → execute
tools_render工具名 → render（可能为 undefined）
tools_description[{ description }]，作为 context.tools 传给 ChatTransport.run
isExecuting是否处于对话执行中；执行中重复发消息会被拒绝、切换会话会被忽略
currentThreadId当前会话 ID，undefined 表示新建会话状态
currentMessages当前会话的历史消息组（HistoryMessageGroup[]）
03

sendMessage

返回 Promise<void>：上一轮未结束时调用，会以 "当前正在执行中" reject；本轮全部走完（含历史落库）后 resolve。 content 可以直接给字符串，框架会包成一段 text0.2.0 新增。

flow
1. 把 message.content 逐段交给 runtime.ChatContent.append 渲染
2. 调用 adapter.ChatTransport.run({ messages: [message], context: { history, tools } })
   —— 返回值需为 AsyncGenerator，假值则直接中止
3. 逐个消费流片段：text / thinking / loading 增量拼接，
   tool-call 走工具流程，未知类型忽略
4. 流结束后合并相邻同角色片段；没有当前会话时调 ThreadList.new()
   （返回假值则中止本轮），再 ThreadList.append 并激活新会话
5. 消息追加到 currentMessages，await MessageHistory.append() 落库；失败则本轮以 error 收尾

任一环节抛错（适配器 run 同步抛出、流片段处理失败、入库失败）都会把 isExecuting 复位、 发一次 task:end，并让 sendMessage 以该错误 reject —— 不会出现“页面卡在执行中”的中间态0.2.0 修复。

call.js
// 两种等价写法
page.sendMessage({ role: "user", content: [{ type: "text", text: "你好" }] });
page.sendMessage({ role: "user", content: "你好" });

page.sendMessage({ role: "user", content: "你好" }).catch(err => {
    // "当前正在执行中"：上一轮还没结束
    // "已取消"：本轮被 page.cancel() 停下（见「主动结束与取消」）
    // 其他：适配器、流式处理或入库失败
});
04

工具调用流程（tool-call）

流片段形如 { id, name, caller, args, status, result? }：

  • pending：先调 runtime.ChatContent.append("assistant", part) 创建工具节点，返回值若为函数则按 id 缓存为结束回调；返回 undefined 时只更新节点状态，不回调。
  • 前端工具（caller: "frontend"）：页面执行 tools_execute[name](args, control)（抛错记为 error）； control 是任务控制句柄，工具里可用它 stop() / cancel() 结束整轮0.2.0 新增。
前端工具有无 render行为
无 render用 { ...part, result, status } 调一次结束回调，并经 ChatTransport.response("tool-result", { id, status, result }) 回传服务端
有 render结束回调调两次：第一次传 { ...part, result, status, render, stop, cancel }，运行时执行 UI 交互并返回 result_ui（stop / cancel 为 0.2.0 起提供）；第二次传 { ...part, result: result_ui, status: status_ui } 做最终渲染。回传给模型的是 result_ui，历史同时保留 result 与 ui: { status, result }
后端工具（caller: "backend"）页面不执行，等流中后续 success / error 片段（携带 result）到达后调结束回调，无需回传
05

主动结束与取消0.2.0 新增

执行中想收手，有两种收法，打断方式相同、收下这一轮的方式不同：

  • stop()：当成功收尾 —— 已产出的内容保留，入库标记 stopped，sendMessage 正常 resolve。业务上“这件事办完了”用它。
  • cancel()：当失败收尾 —— 内容仍是半截，入库标记 cancelled，sendMessage 以 "已取消" reject，界面可据 displayed 撤销。
stop.js
page.stop();     // 主动结束：内容保留，sendMessage resolve
page.cancel();   // 取消：内容可撤销，sendMessage reject("已取消")

// 都返回 boolean：有任务 true，空闲 false
page.sendMessage({ role: "user", content: "写一份长文" }).catch(err => {
    if (err === "已取消") return;   // cancel 才有这条，stop 不会走到 catch
});

page.on("task:end", ({ status, by, displayed }) => {
    // status：complete / stopped / cancelled / error
    // by：stopped、cancelled 时说明是谁发起的（"user" / "tool"）
    if (status === "cancelled") {
        // displayed：本轮已交给 ChatContent.append 的条目，index 即显示顺序
        // 撤不撤、撤哪几条，由界面自己决定
        displayed.forEach(({ index, role, part }) => { /* ... */ });
    }
});
status何时出现入库标记sendMessage界面
complete模型流自然结束completeresolve保留
stoppedstop()，含工具里调用stoppedresolve保留
cancelledcancel()，含工具里调用cancelledreject "已取消"按 displayed 决定
error流式抛错或入库失败不写reject 错误对象保留错误态

在工具里结束这一轮：execute 的第二个参数和 render 收到的数据里都有控制句柄， 调用它的 stop() / cancel() 即可，by 会记成 "tool"。

tool.js
defineTool({
    name: "submit",
    description: "提交订单",
    parameters: { type: "object", properties: {} },
    // 第二个参数是任务控制句柄：taskId / toolCallId / stop / cancel
    execute: (args, control) => {
        control.stop();        // 订单提交完，这一轮到此为止，结果照样入库
        return "已提交";
    },
    // render 收到的数据里也有同一个句柄（data.stop / data.cancel）
    render: (data) => renderCard(data, data.stop)
});

顺序是“先落结果、再收尾”：工具里调 stop() 只会挂个标记，等这次调用的结果渲染完、tool-result 回传完才收尾， 所以这次工具调用不会被丢掉。界面还在等用户点击时被结束，则按 execute 的结果收尾，不再等待。

要点说明
中断底层请求run 拿到的 context.signal 会被 abort，适配器把它透传给 HTTP / 模型请求即可立即停下；不接也能收，只是底层请求会跑完
入库标记stopped / cancelled 都照常写入 MessageHistory.append，消息组带对应的 status；存、丢、或换成自己的标记，由 adapter 自己定
displayed 结构[{ index, role, part }]，part 就是交给 append 的那个片段引用，可直接做 WeakMap 的键找回节点（仅 cancelled 提供）
兜底收尾适配器无视 signal 且分片不再返回时，stopTimeout（默认 5000ms）到点强制收尾，页面不会停在执行中
立即可继续isExecuting 同步复位，收完可以马上发下一条
06

其他方法

方法行为
activeThread(threadId, noLoad?)切换会话：更新高亮；threadId 为 undefined 时清空消息，否则 MessageHistory.load() 后 ChatContent.init()。对话执行中调用会被忽略。noLoad 为内部参数，业务侧不用传
newThread()等价于 activeThread(undefined)
deleteThread(threadId)删除后同步 UI；删的是当前会话则进入新建状态
archiveThread(threadId)归档后同步 UI；归档当前会话也进入新建状态
unarchiveThread(threadId)取消归档，只同步 UI，不自动切换会话
07

任务生命周期事件

用于在整轮对话内挂副作用，例如“新任务来了清掉旧推荐问”“自然完成才追加新推荐问”。

事件触发时机
task:startsendMessage 通过“执行中”校验后立即触发
task:end本轮结束：自然走完、流式出错、主动结束或取消
events.js
const off = page.on("task:end", payload => {
    if (payload.status === "complete") showRecommendedQuestions();
});

page.off("task:end", off);   // 不再需要时

同名事件可注册多个 handler，按注册顺序串行触发；handler 内抛错会被吞掉，不影响 sendMessage 主流程与 Promise 状态； on / off 均链式返回 AuiPage 实例。

payload.ts
type TaskLifecyclePayload = {
    taskId: string;                // 本次 sendMessage 自增生成的唯一 id
    threadId: string | undefined;  // 任务发起时所处的会话 id
    message: ChatContentMessage;   // 本次发送的原始页面消息
};

// task:end 多一个 status；主动结束 / 取消时再带 by，取消另带 displayed（0.2.0 新增）
type TaskEndPayload = TaskLifecyclePayload & {
    status: "complete" | "stopped" | "cancelled" | "error";

    // 仅 stopped / cancelled 时存在：谁发起的结束
    by?: "user" | "tool";

    // 仅 status 为 "cancelled" 时存在：本轮已交给 ChatContent.append 的条目
    displayed?: Array<{
        index: number;                          // 显示顺序，从 0 开始
        role: string;                           // 该条目所属消息的角色
        part: ChatContentPart;                  // 交给 append 的原始片段引用
    }>;
};

complete：流自然走完且入库成功；stopped：被 stop() 主动结束，带 by0.2.0 新增； cancelled：被 cancel() 取消，带 by 与 displayed；error：流式过程抛错或入库失败。

08

消息结构

types.ts
// 文本类片段，text 必须是增量文本，拼接由 AuiPage 完成
type TextPart = {
    type: "text" | "thinking" | "loading",
    text: string
};

// 工具调用片段，字段随调用进度逐步补齐
type ToolCallPart = {
    type: "tool-call",
    id: string,
    name: string,
    caller: "frontend" | "backend",
    args: object,
    status: "pending" | "success" | "error",
    result?: any,
    render?: Function
};

// 页面侧消息（role 放宽为 string，content 是富片段数组）
type ChatContentMessage = {
    role: string,
    content: ContentPart[]
};

// MessageHistory.load() 的返回单元，通常含一轮 user + assistant
type HistoryMessageGroup = { messages: ChatContentMessage[] };

// ThreadList.new() 返回的会话对象，至少含 threadId
type Thread = { threadId: string, title?: string };

工具调用落库时片段固定为 { type: "tool-call", name, args, result, status }； 带 render 的前端工具额外含 ui: { status, result }。
