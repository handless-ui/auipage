Package 04@auipage/fetch

跨端流式 fetch：Node 下走 http/https，浏览器下走原生 fetch + ReadableStream，自动适配；SSE 响应自动按事件缓冲解析。

fetch0.1.0浏览器 + Node
版本0.1.0
依赖@auipage/types
位置packages/fetch
01

用法

client.js
import { fetch } from "@auipage/fetch";

fetch({
    url: "https://example.com/api/chat",
    method: "POST",                                  // 默认 GET
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ message: "hello" })       // 原样发送，不会自动 stringify
})
    .then(res => {
        res.on("data", chunk => console.log(chunk));
        res.on("end", () => console.log("done"));
        res.on("error", err => console.error(err));
    })
    .catch(err => console.error(err));

res 上还能读到 status、ok（2xx 为 true）、headers。

02

三个事件

事件触发时机回调参数
data收到一段数据；SSE 模式下为每个完整事件的 data: 内容(payload: string)
end响应体读取完毕()
error网络或读取出错(err: Error)
03

SSE 自动解析

响应头 Content-Type 含 text/event-stream 时自动开启，不需要任何配置：

  • 按空行（\n\n，也兼容 \r\n\r\n）切分事件，跨 chunk 的事件会自动拼接；
  • data 回调拿到的是去掉 data: 前缀的字符串，不会自动 JSON.parse；
  • 非 SSE 响应行为不变，data 拿到的是原始 chunk。
为什么强调"不自动 parse"：把解析权留给调用方，才能兼容带 [DONE] 结束标记、 多行 data:、以及非 JSON 的自定义格式。
04

两个注意点

  • 非 2xx 不进 catch：用 res.status / res.ok 判断，这样错误响应体也能照常读取。
  • 暂不支持超时与取消：需要时用 AbortController 在外层包装，或直接读 end 事件提前收尾。
