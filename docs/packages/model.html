Package 09@auipage/model

OpenAI 风格 chat/completions 的流式封装：请求拼装、SSE 增量解析、工具调用切片拼接，同协议的其他服务（DeepSeek 等）直接换 baseURL 即可。

model0.2.0OpenAI 协议
版本0.2.0
依赖@auipage/fetch

01

创建实例

model.js
import { Model } from "@auipage/model";

const model = new Model({
    model: "deepseek-chat",                     // 模型名
    apiKey: "your-api-key",
    baseURL: "https://api.deepseek.com/v1"      // 请求时拼接 /chat/completions
});
02

completions 签名

types.ts
model.completions(
    {
        messages: ChatMessage[],   // OpenAI 格式消息
        tools?: Tool[],            // 可选，默认 []；自动取每项 description 作为 tools 提交
        stream?: boolean,          // 默认 false
        timeout?: number,          // 可选，毫秒；到点中止并 reject
        signal?: AbortSignal       // 可选，外部取消
    },
    logback?,                      // (delta: string) => void     正文增量
    thinkback?                     // (reasoning: string) => void  推理过程增量
): Promise<{ content: string, tool_calls: ModelToolCall[] }>

timeout 与 signal 是 0.2.0 新增的入参0.2.0 新增：到点中止 / 外部取消都会让 completions reject。

要点说明
thinkback接收 delta.reasoning / delta.reasoning_content；正文里的 <think>...</think> 会被剥除，剩余内容并入 content。
stream: false两个回调依然会调用，只是在响应结束后各触发一次。
tool_calls0.2.0 修复已把分片的 function.arguments 拼成完整字符串；并行多个调用按 index 归并，不会串味。
失败0.2.0 修复4xx / 5xx、非法响应体、超时、取消统一 reject 一个 Error，消息里带 HTTP 401 这类状态与响应体中的错误说明；流式请求在状态码到达时立即 reject，不会先 resolve 一个空结果。
03

带工具调用的请求

chat.js
await model.completions({
    messages: [
        { role: "system", content: "你是一个助手。" },
        { role: "user", content: "查一下南京今天的天气" }
    ],
    tools: [{
        description: {
            type: "function",
            function: {
                name: "getWeather",
                description: "查询指定城市的天气",
                parameters: {
                    type: "object",
                    properties: { city: { type: "string" } },
                    required: ["city"]
                }
            }
        }
    }],
    stream: true
}, chunk => process.stdout.write(chunk), reasoning => console.log("[think]", reasoning))
.then(({ content, tool_calls }) => console.log(content, tool_calls));

注意 tools 传的是"带 description 的对象数组"， 模型要的不是裸 schema —— 这是本包与 agent 之间的小约定。

04

这个包不是必须的

你的情况更合适的选择代价
只接一家模型、功能简单官方 SDK（openai、@deepseek/sdk）多一个依赖，维护由官方负责
已经用 Vercel AI SDK@ai-sdk/openai + streamText抽象层更厚，生态更全
只要纯文本原生 fetch + 自己解析要处理 SSE 与增量累积
只要非流式原生 fetch 一次 POST没有增量回调，但代码最短

适合“想零依赖、又要一个能直接跑的 OpenAI 兼容客户端”。已经在用官方 SDK 的项目，没有必要为了统一而换掉。
