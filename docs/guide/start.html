Guide 02跑起示例

仓库根目录就是一个可运行的最小示例：一个真实模型、三个适配器、两套运行时、一对前后端工具。

Node 18+pnpmollama 可选
本页目录

01

三条命令

terminal
pnpm i
npm run dev

# http://127.0.0.1:20000/

dev server 由 oipage 提供：同时起 mock 接口与前端页面，改代码热更新。 示例默认接本地 ollama 的 qwen3.5。

02

你应该看到什么

左侧会话列表，右侧对话区。发一句“帮我看一下这个文件”，会依次出现：

  • 思考过程的增量输出（灰色、可折叠）；
  • 后端工具 readPlain 的卡片：执行中 → 完成，带文件内容；
  • 前端工具 showPlain 的卡片：服务端挂起，页面弹窗展示，确认后对话继续；
  • 最后一整段回复，以及会话标题自动生成、刷新后历史仍在。

这一条链路里，流式拼接、工具桥接、历史落库分别由谁负责，下面三章会一层层拆开。

03

没有 ollama 也能跑

示例只依赖 OpenAI 兼容协议。改 src/apis/chat.js 里的三个字段，接任意服务：

src/apis/chat.js
model: {
    baseURL: "http://localhost:11434/v1",   // 换成 https://api.openai.com/v1 等
    apiKey: "",                             // 对应服务的 key
    model: "qwen3.5"                        // 模型名
}

前端不需要改：页面只认 SSE 事件，不认模型厂商。

04

目录结构

tree
src/
├── apis/
│   └── chat.js          服务端接口：Agent + CreateTool 驱动 SSE
├── adapter/
│   └── ...              三个适配器的实现
├── runtime/
│   └── ...              会话列表与对话内容的 DOM 渲染
├── tools/
│   └── ...              后端工具 readPlain 与前端工具 showPlain
├── index.js             页面入口
└── style.css            示例样式

四个目录正对应框架的四块拼图：apis 是服务端编排，adapter 是数据接缝， runtime 是渲染接缝，tools 是工具定义。
