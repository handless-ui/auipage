Guide 05让模型做事

问一句“南京今天天气怎么样”，模型自己决定调哪个工具、传什么参数。这章先手写这个循环，再看 @auipage/agent 省掉了什么。

01

场景：一个查天气的工具

工具本质上是一个带 JSON Schema 的函数描述。模型看到描述后，可能返回“我要调 getWeather， 参数是 { city: "南京" }”，然后停下等你执行。

getWeather.js
export const getWeather = {
    description: {
        type: "function",
        function: {
            name: "getWeather",
            description: "查询指定城市的天气",
            parameters: {
                type: "object",
                properties: { city: { type: "string", description: "城市名称" } },
                required: ["city"]
            }
        }
    },
    execute({ city }) {
        return city + " 今天晴，25°C";
    }
};
02

手写版：循环到底怎么写

关键只有三步：把工具声明带上 → 收到 tool_calls 就执行 → 把结果作为 tool 消息塞回去再请求。 重复到模型不再调工具为止。

loop.js
const registry = { getWeather };

async function chat(messages) {
    while (true) {
        const { content, tool_calls } = await model.completions(
            { messages, tools: [getWeather], stream: true },
            delta => process.stdout.write(delta)
        );

        // 没有工具调用，这一轮就是最终回复
        if (!tool_calls.length) return content;

        // 1. 模型这一轮的“我要调工具”也要进历史
        messages.push({ role: "assistant", content, tool_calls });

        // 2. 逐个执行，再把结果作为 tool 消息回灌
        for (const call of tool_calls) {
            const fn = registry[call.function.name];
            const args = JSON.parse(call.function.arguments);
            const result = await fn.execute(args);

            messages.push({
                role: "tool",
                tool_call_id: call.id,
                content: String(result)
            });
        }

        // 3. 回到 while 开头，带着工具结果再请求一次
    }
}

这段代码已经能跑，但要自己保证：模型名和工具名对得上、arguments 解析失败要兜底、 工具抛错要变成 tool 消息而不是整轮崩掉、循环要有上限。

03

装包版：循环交给 Agent

agent-demo.js
import { Agent } from "@auipage/agent";
import { getWeather } from "./getWeather.js";

const agent = new Agent({
    model: { model: "qwen3.5", apiKey: "ollama", baseURL: "http://localhost:11434/v1" },
    systemPrompt: "你可以使用 getWeather 查询天气。",
    tools: [getWeather]
});

const answer = await agent.generate(
    [{ role: "user", content: "南京今天天气怎么样？" }],
    text  => process.stdout.write(text),   // 正文增量
    think => console.log("[思考]", think)   // 推理增量
);

安装：

terminal
npm install --save @auipage/agent

它做了你刚才手写的那三步，另外补了：工具执行出错时按 status: "error" 上报、 并转成一段文本回灌给模型（不是中断整轮）、推理过程回调、以及整轮只有工具调用时的返回值约定。 担心模型陷入循环时给 new Agent({ maxSteps: 8 })0.2.0 新增，超过上限会抛出明确错误。 页面侧工具还能在 execute(args, control) 里用 control.stop() 主动结束整轮 —— 事情办完了就到此为止， 结果照样进历史0.2.0 新增。

04

工具搬到浏览器执行

有些工具必须在页面上跑：展示文件、弹窗确认、读当前 DOM。做法是把“执行”从服务端挪到浏览器， 服务端只负责挂起和唤醒。

服务端：用 MessageStream + CreateTool 包装工具。带 execute 的仍在服务端跑， 不带的下发页面：

server.js
import { CreateTool } from "@auipage/agent";
import { MessageStream } from "@auipage/core";

const ms = new MessageStream(
    data => res.write("data: " + JSON.stringify(data) + "\n\n"),
    () => res.end()
);
const ct = new CreateTool(ms);

const tools = [
    ct.create(readPlain),     // 带 execute：服务端执行
    ct.create(showPlain)      // 不带 execute：挂起，等页面回传
];

// 页面把结果 POST 回来时，唤醒挂起的那次调用
if (globalThis[data.id]) {
    globalThis[data.id](data.result);
    delete globalThis[data.id];
}

页面：用 defineTool 注册同名工具，render 里做 UI 交互， 它的返回值才是回传给模型的最终结果：

page.js
import { defineTool, AuiPage } from "@auipage/core";

const showPlain = defineTool({
    name: "showPlain",
    description: "在页面上展示一段文本",
    parameters: {
        type: "object",
        properties: { content: { type: "string" } },
        required: ["content"]
    },
    execute(args) {
        return args.content;          // 拿到原始内容
    },
    render({ result }) {
        alert(result);                // 页面交互
        return "用户已看到";           // 这个返回值回灌给模型
    }
});

const page = new AuiPage({
    adapter: { /* 三个适配器 */ },
    runtime: { /* 两个运行时 */ },
    tools: [showPlain]
});

流里的事件长这样，页面对 caller 分流即可：

sse
{ "type": "tool-call", "status": "pending", "id": "c1", "name": "showPlain", "caller": "frontend", "args": { ... } }
{ "type": "tool-call", "status": "success", "id": "c1", "name": "readPlain",  "caller": "backend",  "args": { ... }, "result": "..." }
05

这个包不是必须的

你的情况更合适的选择
工具全在服务端OpenAI Agents SDK、LangChain、Vercel AI SDK
只有一两个工具本章第二节的 while 循环
根本不需要工具只用 @auipage/model 或官方 SDK
必须让浏览器执行工具那就得自己做 SSE 下发 + 结果回传 + 挂起唤醒

它最有价值的地方不是“多轮循环”（那个 20 行能写），而是 同一份工具描述，服务端和浏览器各执行一半。如果工具都在服务端，别的框架同样好用。
