Guide 03一个包都不用

先不装任何依赖：一个输入框、一个发送按钮、一段原生 fetch。把它跑通，你就知道后面每个包到底替你省了什么。

01

今天要做的东西

一个最朴素的智能体页面：输入一句话，服务端逐字把回复推回来，页面实时显示。

它由两个文件组成，都不需要 npm install：

文件干什么
server.jsNode 内置 http 起接口，把回复拆成 SSE 事件逐条写回
index.html页面用原生 fetch 读流，把事件拼成文字
为什么拆成两个进程？ 模型的 key 和调用逻辑必须留在服务端，浏览器只拿 SSE 事件。 这一层分离，后面的所有包都沿用。
02

服务端：把回复拆成事件

server.js
import http from "node:http";

http.createServer((req, res) => {
    // 跨域，方便页面从别的端口访问
    res.setHeader("Access-Control-Allow-Origin", "*");
    res.setHeader("Access-Control-Allow-Headers", "Content-Type");

    if (req.method === "OPTIONS") return res.end();

    if (req.method !== "POST" || req.url !== "/api/chat") {
        res.writeHead(404);
        return res.end();
    }

    let body = "";
    req.on("data", chunk => body += chunk);
    req.on("end", () => {
        const { messages } = JSON.parse(body);

        res.writeHead(200, {
            "Content-Type": "text/event-stream;charset=utf-8",
            "Cache-Control": "no-cache"
        });

        // 假装这是模型回复，逐字推送
        const reply = "你说的是：" + messages.at(-1).content;
        let i = 0;

        const timer = setInterval(() => {
            if (i >= reply.length) {
                clearInterval(timer);
                res.write("data: [DONE]\n\n");
                res.end();
                return;
            }
            res.write("data: " + JSON.stringify({
                type: "text",
                text: reply[i++]
            }) + "\n\n");
        }, 50);
    });
}).listen(3000, () => console.log("http://127.0.0.1:3000"));

要点只有一个：每条消息以 data: 开头，以空行结束。 SSE 协议就这么简单，浏览器会自动帮你按事件切分——但原生 fetch 不会。

03

页面：一句话发出去，逐字接住

index.html
<!DOCTYPE html>
<meta charset="UTF-8">
<input id="q" placeholder="说点什么">
<button id="send">发送</button>
<div id="out"></div>

<script>
const out = document.querySelector("#out");

document.querySelector("#send").onclick = async () => {
    out.textContent = "";

    const res = await fetch("http://127.0.0.1:3000/api/chat", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify({
            messages: [{ role: "user", content: document.querySelector("#q").value }]
        })
    });
    if (!res.ok) throw new Error("HTTP " + res.status);

    const reader = res.body.getReader();
    const decoder = new TextDecoder();
    let buffer = "";

    while (true) {
        const { done, value } = await reader.read();
        if (done) break;

        buffer += decoder.decode(value, { stream: true });

        // 按空行切成完整事件；最后一段可能还没收完，留到下一轮
        const events = buffer.split("\n\n");
        buffer = events.pop();

        for (const event of events) {
            const line = event.split("\n").find(l => l.startsWith("data:"));
            if (!line) continue;

            const payload = line.slice(5).trim();
            if (payload === "[DONE]") return;

            const data = JSON.parse(payload);
            if (data.type === "text") out.textContent += data.text;
        }
    }
};
</script>

跑起来：node server.js，再用任意静态服务器打开 index.html （例如 npx serve .），输入一句话就能看到逐字输出。

04

你已经踩到的坑

这段代码能跑，但把真实模型接上来之后，下面每一条都会变成 bug：

坑为什么会发生谁替你处理
事件被切在半个 chunk 上网络传输不按事件边界分片，data: 可能被截成两半@auipage/fetch 的缓冲切分
服务端用 CRLF 换行\r\n\r\n 不是 \n\n，按后者切会整段粘住@auipage/fetch 兼容两种
[DONE] 不是 JSON直接把每条 data: 丢给 JSON.parse 会抛错上层封装先行判断
非 2xx 不抛错原生 fetch 只把状态放进 res.status用 res.ok 自己判断
Node 里没有 readerres.body.getReader() 只在浏览器存在@auipage/fetch 自动换 http
事件不止文本思考增量、工具调用、工具结果都要走同一条流AuiPage 按类型分发
05

这一步，你完全可以自己做

上面两个文件加起来不到 80 行，没有任何一个 auipage 包参与。如果你的需求只有“发一句话、收一段流式文本”， 到这里就可以结束了，不需要往下看。

继续往下，是为了解决这段代码做不到的三件事：接真实模型、让模型调工具、管理多个会话。 每一章都会同时给出“装包版”和“自己写版”，你可以只挑需要的部分。
