Guide 06装框架

代码开始散在每个事件回调里时，把它们收进两个接口：Adapter 管数据，Runtime 管界面。AuiPage 只负责在正确的时候调用它们。

AuiPage3 Adapter2 Runtime
01

场景：三件事开始互相纠缠

走到这一步，页面代码里通常已经混了三类逻辑：

逻辑散在哪加一个功能时的连锁反应
流式拼接每个 onData 回调里都有 +=加“停止生成”要改所有回调
工具状态卡片节点自己记 pending / success换个 UI 就得重写一遍状态机
会话与历史手动维护 currentThreadId、切会话时清空加“归档”要同时改列表、消息区和存储

AuiPage 把这堆流程收成固定顺序，业务侧只实现接口。

02

两条接缝

接缝实现什么换掉它会怎样
ChatTransportAdapterrun({ messages, context }) 返回 AsyncGenerator换模型服务、换 API 协议、甚至换成假数据
MessageHistoryAdapterload(threadId) / append(threadId, group)从 localStorage 换成数据库或 REST
ThreadListAdapterlist / new / delete / archive / unarchive换会话存储方式
ChatContentRuntimeinit / append从 DOM 换成 React / Vue / 小程序
ThreadListRuntimeinit / active / append / delete / archive / unarchive换侧边栏的渲染方式
03

装配：从 console 开始

先不碰 DOM，用四个 console.log 看清流程。装好依赖后，这段可以直接 node demo.js：

demo.js
import {
    AuiPage,
    ChatTransportAdapter, MessageHistoryAdapter, ThreadListAdapter,
    ThreadListRuntime, ChatContentRuntime
} from "@auipage/core";

const page = new AuiPage({
    adapter: {
        ChatTransport: new ChatTransportAdapter({
            async *run({ messages }) {
                for (const ch of "你好，我是 auipage。") {
                    yield { type: "text", text: ch };
                }
            }
        }),
        MessageHistory: new MessageHistoryAdapter({
            load: async () => [],
            append: async () => {}
        }),
        ThreadList: new ThreadListAdapter({
            list: async () => [],
            new:  async () => ({ threadId: "t1", title: "新会话" })
        })
    },
    runtime: {
        ThreadList: new ThreadListRuntime({
            init: threads => console.log("会话列表：", threads)
        }),
        ChatContent: new ChatContentRuntime({
            append: (role, part) => {
                if (part.type === "text") {
                    let buf = part.text;
                    return text => console.log(buf += text);
                }
            }
        })
    }
});

await page.sendMessage({
    role: "user",
    content: [{ type: "text", text: "你好" }]
});

你只做了一件事：告诉框架“流从哪来、历史存哪、界面怎么画”。 流式拼接、首轮结束才建会话、历史入库的时机，全部由 AuiPage 按固定顺序调用。

04

把前几章接进来

对话：上一章的 Agent 包成一个生成器，run 直接返回它。

adapter/chatTransport.js
import { ChatTransportAdapter, generator } from "@auipage/core";

const chatTransport = new ChatTransportAdapter({
    run: ({ messages, context }) => generator((next, done, error) => {
        agent.generate(
            messages,
            text  => next({ type: "text", text }),
            think => next({ type: "thinking", text: think })
        ).then(done, error);
    })
});

历史：append 收到的是“一轮消息组”，换存储只改这一个方法。

adapter/messageHistory.js
const messageHistory = new MessageHistoryAdapter({
    load: (threadId) => {
        const raw = localStorage.getItem("history:" + threadId);
        return raw ? JSON.parse(raw) : [];
    },
    append: (threadId, group) => {
        const key = "history:" + threadId;
        const list = JSON.parse(localStorage.getItem(key) || "[]");
        list.push(group);
        localStorage.setItem(key, JSON.stringify(list));
    }
});

界面：文本片段返回一个更新函数，后续增量只碰这个节点；工具片段返回结束回调。

runtime/chatContent.js
const chatUI = new ChatContentRuntime({
    init: () => { chatEl.innerHTML = ""; },
    append: (role, part) => {
        const node = renderPart(role, part);
        if (part.type === "text" || part.type === "thinking") {
            return text => { node.textContent += text; };   // 只更新这一个节点
        }
        // tool-call：返回结束回调，用于更新卡片状态
    }
});

完整时序（工具两次回调、执行中切会话、任务生命周期事件）见 core 参考。

05

四种常见组合

没有“标准全家桶”。按项目形态挑一种即可，后面想加再补：

组合适合什么项目页面侧
model脚本、CLI、批处理，只要模型输出不需要
model + agent服务端跑工具循环，前端自己画自己处理 SSE 与渲染
core + agent完整智能体网页：会话、历史、工具卡片两个 Runtime
core + 自己的 transport已有后端协议，或要用假数据做 UI两个 Runtime

注意 core 与 agent 不是绑定关系：ChatTransportAdapter.run 里放什么都行， 包括一个只 yield 固定文本的生成器。

06

这个包不是必须的

你的情况更合适的选择
只做一个 React 聊天页assistant-ui、Vercel AI SDK 的 useChat
不需要会话列表和历史自己维护一个消息数组 + 渲染循环
只有一个页面、一个框架现成聊天 UI 库更省事
要跨 DOM / React / Vue 复用同一套流程这时候 Adapter + Runtime 才划算

判断标准：如果你预计会换一次 UI 框架，或者服务端要同时喂 Web 和桌面端， 把流程抽出来就是值得的；否则不必为了“架构感”提前抽象。
