Guide 04接真实模型

上一章的回复是写死的。这一章把它换成任意 OpenAI 兼容服务，先自己解析，再决定要不要装 @auipage/model。

OpenAI 兼容SSEstream
01

手写版：只多一段解析

协议没有变，还是 SSE，只是事件里的 JSON 变成了 choices[0].delta。把上一章的 reply 换成一次真实请求：

server.js
const baseURL = "http://localhost:11434/v1";   // 任意 OpenAI 兼容服务
const apiKey = "ollama";
const modelName = "qwen3.5";

const res = await fetch(baseURL + "/chat/completions", {
    method: "POST",
    headers: {
        "Content-Type": "application/json",
        "Authorization": "Bearer " + apiKey
    },
    body: JSON.stringify({
        model: modelName,
        messages,
        stream: true
    })
});

const reader = res.body.getReader();
const decoder = new TextDecoder();
let buffer = "";
let content = "";

while (true) {
    const { done, value } = await reader.read();
    if (done) break;

    buffer += decoder.decode(value, { stream: true });
    const lines = buffer.split("\n");
    buffer = lines.pop();                       // 最后一行可能不完整

    for (const line of lines) {
        const trimmed = line.trim();
        if (!trimmed.startsWith("data:")) continue;

        const payload = trimmed.slice(5).trim();
        if (payload === "[DONE]") continue;

        const delta = JSON.parse(payload).choices[0].delta;

        if (delta.reasoning_content) {          // 有的模型会推思考
            console.log("[思考]", delta.reasoning_content);
        }
        if (delta.content) {
            content += delta.content;
            process.stdout.write(delta.content);
        }
    }
}

能出字了。但它只处理了“纯文本回复”——模型一旦调用工具， delta.tool_calls 是按 index 分片到达的，arguments 还是半个 JSON，这段代码会直接漏掉。

02

装包版：同一件事，三行收尾

model-demo.js
import { Model } from "@auipage/model";

const model = new Model({
    model: "qwen3.5",
    apiKey: "ollama",
    baseURL: "http://localhost:11434/v1"
});

const { content, tool_calls } = await model.completions(
    { messages, stream: true },
    delta => process.stdout.write(delta),          // 正文增量
    think => console.log("[思考]", think)            // 推理增量
);

安装：

terminal
npm install --save @auipage/model
03

它到底替你做了什么

细节手写要处理@auipage/model
请求拼装URL 拼接、鉴权头、tools 映射构造时给三个字段，其余自动
SSE 切分data: 前缀、空行、跨 chunk 拼接内置
正文累积自己维护 content += delta.content返回完整 content
推理过程reasoning_content / reasoning 两种字段名thinkback 统一收口
<think> 标签从正文里剥离，处理标签被切断的情况自动剥离并冲刷残留
工具调用0.2.0 修复按 index 归并，拼完 arguments 再 parse返回已拼好的 tool_calls
非流式两种响应结构分别取值同一套回调，结束时触发一次
失败0.2.0 修复4xx 也要读出错误体，别让 Promise 挂着统一 reject 一个带 HTTP 401 与错误说明的 Error

所以调用处只要一个 catch：网络、超时、鉴权失败、非法响应体都从这里出来，不会卡住也不会把进程带崩。

中断也有出口0.2.0 新增：构造时给 timeout 到点自动中止，或在选项里传 signal，外部 abort() 后本轮 generate 直接 reject —— 配合 AuiPage.stop() / cancel() 就能做“停止生成”。

04

这个包不是必须的

你的情况更合适的选择
只接一家模型、功能简单官方 SDK（openai、@deepseek/sdk）
已经在用 Vercel AI SDK@ai-sdk/openai + streamText
只要纯文本、不需要工具上一节的手写版就够
想完全掌控每个字节原生 fetch + 自己解析

什么时候它才值得：你既要流式、又要工具调用，还希望零依赖、能随时换兼容服务。 如果只需要文本，手写那一版反而更透明。
